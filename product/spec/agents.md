# Agents

- **backend-interface:** A model backend answers one request with reply text and its cost, so any model can be plugged in without the game knowing which.
- **no-model-yet:** Every model no backend serves is refused, so nothing can spend money by accident.
- **openrouter-backend:** A model named `openrouter/<model id>` plays through OpenRouter's chat completions with the pirate's tools: its tool call comes back in the one reply form, and its cost is the reply's own usage figure, totalled in the run's manifest. A reply that gives no cost stops the run, since the spending cap couldn't count it. Default, Al to confirm: the model may answer without a tool, which counts as a bad reply, and thinking off sends no reasoning setting.
- **reasoning-looked-up:** Whether an OpenRouter model can reason comes from OpenRouter's free model listing (its supported parameters include `reasoning`), looked up once when a live run starts and saved with the run's config, so a model that can't reason writes its thought in its reply and a replay needs no network; a pirate's `thinks` in the config (`built-in` or `in-reply`) overrides it, and a model the listing can't speak for keeps the backend's own way. Default, Al to confirm.
- **key-from-the-environment:** A backend's key comes only from its environment variable, which `.env.example` names with no value, and a missing key stops a run before the game starts, saying which variable to set.
- **check-keys:** `treasure-island check-keys` prints one line per model backend: its key isn't set, is set but rejected, or works, with what the provider says for free (for OpenRouter, what the key has spent and its limit; for Adaption, how many hosted models it can use). It never asks a model anything and never prints any part of a key, and it fails if a key that is set doesn't work, so keys can be checked in seconds without spending.
- **model-per-pirate:** A pirate's config may name a model, and that pirate plays through the LLM brain while the rest of the crew plays the config's brain, so one crew can mix models and scripts.
- **normal-temperature:** Models play at their provider's default temperature, not zero, so repeated runs vary and rates can be measured, while each run still replays exactly from its stored replies.
- **one-request-per-turn:** Each LLM turn is one request holding only the system prompt, the turn's text and the pirate's tools as tool definitions, so requests stay small and every model is asked the same thing.
- **reply-is-a-tool-call:** A backend answers with JSON text naming one tool and its arguments, and the reasoning when thinking is on, so any provider's tool call reaches the game in one form.
- **ask-once-more:** A reply that isn't a valid tool call is recorded and counts as a failed action: the pirate is told why and asked again, and after `failed_tries` refusals in one turn (default 2) its turn passes with no action.
- **refusals-noted:** Every reply that isn't a valid action is noted loudly, because Al finds them interesting: that turn's story says in plain words how many of the pirate's replies weren't valid actions and whether its turn passed, the run's manifest counts them for each pirate, a turn the spending cap stopped part way included, and the run command ends with a warning naming the pirates and their counts.
- **reply-cap:** Each reply, its thought and its tool call together, is capped at a small output size, `reply_tokens` in the config (default 300); a model's own built-in reasoning has its own budget (`model-reasoning`). A reply the token limit cut off before it named a tool is recorded as a refused reply that says so, never as an empty one, and the pirate is told its answer ran out of room. With thinking on, the refused reply also keeps whatever reasoning came back before the cut, as its `thinking`, so the record shows what the model spent the room on; the try is still lost (v2, Edu to confirm).
- **plays-then-replays:** A whole game plays through a fake backend, then replays byte-identical from the replies its folder stored, with no backend at all, so an LLM game costs money once and is free to check ever after.
- **adaption-backend:** A model named `adaption/<model id>` is served by Adaption's Responses API through its Python SDK, with the pirate's tools as function tools, so our runs spend the hackathon's Adaption credits.
- **adaption-waits:** A call to Adaption streams its reply and waits up to 10 minutes for it, and the SDK never tries it again on its own, since a reply that reasons for thousands of tokens can take longer than a minute, which is as long as the SDK, and Adaption's server for a reply that isn't streamed, will wait; a call that really drops, a stream that ends before the whole reply included, is tried again as `retries-dropped-calls` says, so the story says so (default, Edu to confirm).
- **adaption-cost:** An Adaption reply's cost comes from its token usage at the model's listed rate in credits per million tokens, a model with no listed rate is refused before anything is asked, and a reply that gives no token usage stops the run, since the spending cap couldn't count it; the manifest totals it as `cost_credits`, apart from `cost_usd`, which counts only dollars, and the spending cap counts a credit as a dollar (default, Al to confirm).
- **free-runs-in-ci:** A full game with each scripted brain completes in CI without an API call or a key, so the whole path from config to logs is proved at no cost.
- **committed-runs:** A game of each scripted brain is committed under `runs/`, passes the event-log validator and replays, so the visuals have evidence to build from without rerunning anything; so is seed 0 of each incentives cell (`experiments/spec/incentives.md`), one game per condition, so every cell has a game anyone can open and replay.
