# Runs

- **one-game:** `run` and `replay` have one path, the real game, and a config that names no `brain` is refused with a message saying so, so nobody has to ask which game a config plays.
- **run-command:** `treasure-island run CONFIG --seed N` plays one game into a new folder under `runs/`, and never overwrites an earlier run, so every result keeps its evidence.
- **run-folder:** A run folder holds `events.jsonl`, `story.txt`, `pirates-log.txt`, `replies.jsonl`, `config.json` and `manifest.json`, so it's all anyone needs to check or rebuild that run.
- **replies-keyed:** Every model reply is stored under a key made from everything that shaped the request (agent, model, prompt, temperature and seed), so a reply is only ever reused for the request that earned it.
- **manifest-varies:** `manifest.json` holds what varies between identical runs (times, cost, cache hits, and the prompt base file's hash with the system prompt it rendered, since the base can be edited under an unchanged config), so nothing else in the folder has to.
- **replay-by-actions:** `treasure-island replay runs/<name>` feeds each turn's recorded attempts back into today's game under the run's saved config, asking no model, and fails, naming the first turn that differs and what differs, unless every turn's rule-decided record matches (who acted, what it saw of its square and neighbours, what it tried and did, what it was shown of the scroll, where everyone ended up) and the game ends the same way. The prompt, the story's wording and the stored replies don't enter into it, so a changed prompt doesn't break an old game while a changed rule does, and a rule change that should leave old games alone goes behind a flag in the config, which the run records. No keys and no network, so anyone can check a committed run for free.
- **replay-checks:** The pull request checks replay only a short named list of games, kept in one place in `src/treasure_island/replay.py`: the examples, the committed runs (of the incentives sweep, one game per cell: `sweep-games-kept`) and a few chosen result games. `make replay-all` replays every committed game on demand, outside the pull request checks, so hundreds of committed games don't slow every pull request and any of them can still be checked with one command.
- **sweep-games-kept:** (v2) Every game of the incentives sweep, those played again included, stays committed in `runs/<cell>/`, one folder for each row of `experiments/incentives-findings/games.csv` and more for the replays, and only one game per cell is on the replay list, so a finding can be checked against the games it counts while the pull request checks stay short. Every game the findings count replays; an attempt they don't count may not, stays as the record of what was tried, and shows as a failure in `make replay-all`.
- **same-in-every-process:** The same config and seed give byte-identical files and GIFs in separate processes, whatever Python's hash seed, apart from the times in `manifest.json`, and another seed gives another valid game, so anyone can repeat a run exactly.
- **no-silent-model-calls:** With no backend, a reply that isn't stored fails instead of calling anything, so checking a run can never cost money.
- **plays-live:** `treasure-island run` opens the live view by default, and `--no-watch` turns it off for CI, so you always watch a game play.
- **paced-from-cache:** While it's being watched, a run plays turn by turn at a watchable pace however fast its pirates answer, so a game never jumps to the end.
- **cache-across-runs:** A model's reply can be reused from an earlier run's answer to the same request, with a copy kept in the new run's folder, so a repeat spends nothing and its folder alone can regenerate it.
- **same-answer-wins:** When two runs answered one request differently, the run that started last wins, going by the start time committed in each manifest, so the same command plays the same game on every machine; a run stopped before it wrote a manifest counts as the oldest, and runs that started at the same moment go by folder name.
- **no-cache:** `--no-cache` asks for every model reply again instead of reusing earlier runs' answers, and writes a new run folder, so a game can be regenerated. Scripted brains ask nothing, so with them it plays the same game.
- **cost-before-run:** Before a run whose crew has a model, the command prints the most model calls it can make (each such pirate's turns, times the `failed_tries` a turn allows, since a reply that isn't a tool call is one of those tries), how many replies earlier runs got from those pirates with this seed, and an upper estimate of tokens, the thinking budget included, and, where the model's price is known, of cost, so nobody is surprised by a bill; a cost under a cent shows its first two significant digits, such as $0.0042, so a paid run never reads as free, and an Adaption model's cost is shown in Adaption credits, the unit it bills in, not dollars.
- **yes-before-spending:** A run asks for a yes before its first request that no stored reply answers, `--yes` skips the question, and nothing in CI passes it, so money is only spent on purpose; anything but a yes stops the run before it spends and leaves no run folder behind, since it played nothing it couldn't play again.
- **spending-cap:** `--spend-up-to` caps what one run spends, default, Al to confirm: 1 dollar; once a run has spent its cap it asks its models nothing more, so it can only overshoot by one reply.
- **cached-is-free:** A stored reply, from this run or an earlier one, costs nothing and counts nothing against the cap.
- **stops-cleanly:** A run that stops at its cap keeps every turn it played, its story's last line says why it stopped, and it replays like any other run.
- **debrief-command:** `treasure-island debrief RUN...` asks every model pirate in each finished run the fixed questions in `prompts/debrief/questions.md`, one after another in one conversation, each pirate starting from what it was shown on its last asked turn and what it did, then told how the game ended (`prompts/debrief/ending.md`), with no tools, and writes `debrief.jsonl` beside the run, one line per pirate with each question and its answer, so what a pirate says once the game is over sits with the game and never changes it.
- **debrief-cached:** A debrief's replies are stored in the run's `debrief-replies.jsonl` and reused, and it asks for a yes and keeps to `--spend-up-to` as a run does, so a debrief costs once, is free to write again, and spends nothing unasked.
